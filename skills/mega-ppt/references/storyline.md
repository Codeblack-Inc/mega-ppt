# 스토리라인 설계

## 피라미드 원칙
1. **결론 먼저**: 첫 내용 슬라이드(또는 요약)에 핵심 주장/권고를 둔다.
2. **근거 3개 내외**: 결론을 받치는 이유를 MECE(겹치지 않고 빠짐없이)로 묶는다.
3. **각 근거에 데이터**: 근거마다 숫자·사례 슬라이드로 뒷받침.

## 액션 타이틀 규칙
- 명사구 금지, **주장하는 문장**으로. "매출 추이" → "매출은 3년간 2배 늘었지만 이익률은 절반으로 줄었다"
- 슬라이드 본문은 타이틀을 증명하는 역할만 한다. 증명하지 않는 요소는 뺀다.
- 한 줄 40자 안팎, 최대 2줄.
- **타이틀 테스트**: 타이틀만 이어 읽어서 이야기가 되는가?

## 덱 유형별 뼈대

**의사결정 보고 (경영진)** — 표지 → 요약(결론+요청) → 현황 → 원인 → 옵션 비교 → 권고안 → 실행계획 → 결정 요청

**제안서** — 표지 → 고객 과제 → 우리의 해법 → 차별점 → 사례/증거 → 추진 방식 → 일정·비용 → 마무리

**피치덱** — 표지 → 문제 → 해법 → 시장 규모 → 제품 → 트랙션 → 비즈니스 모델 → 경쟁 → 팀 → 투자 요청

**분석/리서치 공유** — 표지 → 핵심 발견 3개 → 발견별 섹션(데이터) → 시사점 → 다음 단계

## 사용자에게 보여줄 아웃라인 형식
```
1. [cover] 테스트타임 연산 확장 기반 한국어 추론형 LLM 개발
2. [toc]
3. [divider] 01 연구 배경
4. 모델 크기 대신 추론 시 연산을 늘리는 것이 새로운 성능 확장 축이 되었다   — chart + bullets + table / callout
5. 기존 한국어 LLM 학습은 정답 모방 중심이라 다단계 추론으로 일반화되지 않는다   — label+cards → label+cards
...
```
헤드라인 옆에 계획한 패널 조합을 적어 두면 사용자가 장표 구성을 미리 가늠할 수 있다.
